# Database Integration Guide - System Architect & LLD Backend Agents

## Overview
The database has been integrated to store outputs from:
1. **System Architect Agent** - Generates system architecture documents
2. **LLD Backend Agent** - Generates backend low-level design documents

## Database Schema

### 1. SystemArchitectureDocument Table
Stores system architecture documents generated by the System Architect Agent.

**Columns:**
- `id` (Integer, PK): Auto-incremented primary key
- `analyst_document` (Text): Input analyst document
- `output` (Text): Generated architecture markdown content
- `session_id` (String): AgentContext session ID
- `created_at` (DateTime): Timestamp of creation

### 2. LLDBackendDocument Table
Stores backend LLD documents generated by the LLD Backend Agent.

**Columns:**
- `id` (Integer, PK): Auto-incremented primary key
- `user_input` (Text): Original user request
- `requirement_doc` (Text): Requirements document input
- `architecture_doc_id` (Integer, FK): References SystemArchitectureDocument.id
- `output` (Text): Generated backend LLD markdown content
- `session_id` (String): AgentContext session ID
- `created_at` (DateTime): Timestamp of creation

### 3. LLDDocument Table
Existing table for Frontend/Generic LLD agent outputs (unchanged).

## Integration Points

### For System Architect Agent
Update [src/system_architect_agent/sysaapp.py](src/system_architect_agent/sysaapp.py) to:
1. Import database functions
2. After `state.architecture_output` is generated, save it:

```python
from database.db import save_system_architecture_document

# After architecture_output is generated
arch_record = save_system_architecture_document(
    db=db_session,
    analyst_document=state.analyst_document,
    output=state.architecture_output,
    session_id=context.session.session_id
)
```

### For LLD Backend Agent
Update [src/lld_backend_agent/lldbapp.py](src/lld_backend_agent/lldbapp.py) to:
1. Import database functions
2. After LLD output is generated, save it with architecture reference:

```python
from database.db import (
    save_lld_backend_document,
    get_latest_system_architecture_document
)

# Get the latest architecture document
arch_doc = get_latest_system_architecture_document(db=db_session)

# After LLD output is generated
lld_record = save_lld_backend_document(
    db=db_session,
    user_input=user_input,
    requirement_doc=requirement_doc,
    output=lld_output,
    architecture_doc_id=arch_doc.id if arch_doc else None,
    session_id=context.session.session_id
)
```

## Database Initialization

The database is automatically initialized when `init_db()` is called:

```python
from database.db import init_db

init_db()  # Creates all tables if they don't exist
```

## Usage Example - Full Pipeline

```python
from database.db import (
    init_db, 
    get_db,
    save_system_architecture_document,
    save_lld_backend_document,
    get_lld_backend_documents_by_architecture
)

# Initialize database
init_db()

# Get database session
db_session = next(get_db())

# 1. System Architect Agent runs and produces output
arch_output = run_architect_agent(analyst_doc)
arch_record = save_system_architecture_document(
    db=db_session,
    analyst_document=analyst_doc,
    output=arch_output,
    session_id="session-1"
)

# 2. LLD Backend Agent runs using architecture as input
lld_output = run_backend_lld_agent(requirement_doc, arch_output)
lld_record = save_lld_backend_document(
    db=db_session,
    user_input="Generate backend",
    requirement_doc=requirement_doc,
    output=lld_output,
    architecture_doc_id=arch_record.id,
    session_id="session-1"
)

# 3. Query all LLD documents for this architecture
related_llds = get_lld_backend_documents_by_architecture(
    db=db_session,
    architecture_doc_id=arch_record.id
)

print(f"Architecture: {arch_record.id}")
print(f"Related LLD Backends: {len(related_llds)}")
```

## Key Features

✅ **Traceability**: Track which LLD Backend documents were generated from which System Architecture documents  
✅ **Session Management**: All documents tagged with session IDs for correlation  
✅ **Timestamps**: Automatic creation timestamps for audit trails  
✅ **Query Flexibility**: Multiple retrieval methods (by ID, by architecture, latest, all)  
✅ **Type Safety**: Full SQLAlchemy ORM models with proper relationships
